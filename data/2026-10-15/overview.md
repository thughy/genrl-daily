**一句话结论**：这期最值得学的是 IsoVRBench 量出来的一件事——**一个 reward model 只能感知它训练对里「单独变化过」的属性**。视频 RM 的训练和评测都用「两个不同生成器各出一段」的人评偏好，于是 RM 学会了认生成器（只看生成器身份就能猜中 74–78% 的标签），却看不出最基本的帧顺序（打乱 6 段，人 100%，最好的 RM 60.8%）。我在 200 对官方数据上复核：一个不看顺序、只读重编码残留的统计就有 59%，和最好的 RM 没有可分辨差别。

**对我们训练的含义**：

- 视频 RL 用 VideoReward / VLM judge 之前，先在 IsoVRBench 的 Shuffle / Hold 对上测它（官方 HF 数据 + score.py），不到 ~60% 就等于对时序不设防。
- 同一篇里还有一个反直觉的结果：RM 学会看顺序之后，生成器的 Motion_Order_Understanding 并没有涨（19.9 → 17.1 / 17.7 / 13.8）。「RM 看得见」只是必要条件，base 很少产生正确顺序时 RL 学不会（P5 的又一例）。
- 统一模型做自奖励时（Self-Verifier Capture）：裁判读出要锁快照，再给 1/16 的 rollout 加外部锚；自己生成的标签刷新不了裁判。
- **音视频世界模型**：本期三条测量合起来（收敛 4）说明，单个自动分数（VideoReward、AV-Align、JavisScore、笼统的「物理是否合理」提问）都不能单独当音视频 RL 的 reward 裁判。上 RL 前先做两件零训练成本的事：在 IsoVRBench Shuffle / Hold 上测候选视频 RM；用 SyncReward 的留出 bench 或 VA-Judger 的人评对测同步 reward。AR 采样器上做 GRPO 时，分叉点按组内方差占比来选（收敛 1、Fork-NFT 1.9%）。

### 跨篇收敛（G5）

**收敛 1（P11 候选，可信度：独立印证·中低）：可归因的学习信号来自「受控对比」——共享 seed / 前缀 / 父状态 / 生成器，只改一个因素，差异才归因得到这个因素上；独立生成的样本之间的比较，大部分在比较无关因素（生成器身份、seed 运气）。**

| 来源 | 比较怎么受控 | 受控 vs 不受控 | 证据强度 |
|---|---|---|---|
| IsoVRBench（2610.17234） | 同一锚视频只改一个属性 | 偏好基准标签 74–78% 可由生成器身份预测；干预对训 RM 在 VBench-2.0 +3.8 | 测量站得住；RM 增益只在 1/4 基准上 |
| D2G（2610.17882） | 共享早期 ODE 前缀（TPSS）后再分叉 | 去掉共享前缀 Fidelity 85.60 → 70.25 | 单次运行，存疑 |
| FlowCred（2610.18142） | 同 seed 网格 | prompt credit 方差 −27%、生成器 advantage 方差 −31% | 有 3 run，最终指标只 +0.4 |
| SaTPO（2610.19563，今日批次） | 不安全 prompt 与安全改写共享父状态 + 同噪声 | 对「独立双轨迹」（D3PO 式）同预算：I2P PV 12.40 → 9.80，IP 8.20 → 5.74；FID 26.50 vs 26.81 | 单次运行 |
| Fork-NFT（10-14 已读） | 共享前缀兄弟组 | 晚分叉时视频 reward 组内方差只占 1.9% | 反面边界 |

- **反面与边界**：共享太多会把信号也共享没了——Fork-NFT 晚分叉组内方差 1.9%；D2G 的分叉点 t_crit < 0.2 不够；VARI（2610.18189，与 FlowCred 同组）的「同 seed 优先」只多 +0.11（51.17±0.13 vs 51.06±0.19），在噪声内。所以分叉点 / 共享程度是一个要按「组内方差占比」来定的旋钮，不是越多越好。
- **独立性**：IsoVRBench、D2G、SaTPO 三组互不引用；FlowCred 与 VARI 同组只算一个来源。
- **升为正式原理的条件**：任一工作在同一模型上做「共享程度扫描」（组内方差占比 vs 最终增益）的干预对照；或我们自己在视频 GRPO 里扫分叉步。

**收敛 2（支持 P5）：reward 能感知 ≠ 生成器能学会。** IsoVRBench 中三个 reward 都没让 Motion_Order_Understanding 上涨（base 19.9）；与 UMM-Reflection「RL 主要在 base 已有样本里重新分配」一致。

**收敛 3（细化 L7 / CoRe）：自奖励失败有两种可分开测的机制。** capture（裁判与策略共享权重，判别力被改写：固定探针 AUC 0.812 → 0.630）和 staleness（裁判冻结，判别力还在，但与外部评审的相关随漂移 0.76 → 0.18）。合看 UMM-Reflection：RL 后探针 AUC 不变（0.804 → 0.815）只在 reward 来自外部时成立。CoRe 的「共演化 RM」要加限定：共演化必须用独立标签。

**P10 旁证（不计独立来源）**：MaskSense（离散 MGM）报告「沿采样轨迹重遮盖会早期塌缩，随机重遮盖最好」（Fig.5c，只有文字），与 P10「训练状态取自采样器实际访问分布」方向相反，记为弱冲突；FDDA（解码器训练–生成错配）为弱支持。

**收敛 4（新，细化 L7 / metrics.md；可信度：独立印证·中）：单个笼统的自动分数测不出具体属性，也对不上人。** 四个独立来源、四种模态和属性：

| 来源 | 测的是什么 | 结果 | 证据强度 |
|---|---|---|---|
| IsoVRBench（UW / Meta） | 视频 RM 对帧顺序 | 最好 60.8%，6/9 不高于随机；我测的不看顺序统计 59.0% | 站得住（我复核过） |
| VA-Judger（ShareLab-SII，10-14） | 音视频单项指标 vs 人评 | 一致率 50–57%，域外 44–52% | 存疑（单篇，测量部分可信） |
| SyncReward（RUC / 微信） | 直接优化 AV-Align 自身指标 | 0.306 → 0.420，人偏好反而低 | 存疑（作者自报） |
| PhyMetric（今日批次，只读摘要） | 物理合理性 | 针对性问题换成一个笼统提问，裁判准确率降到随机 | 证据不足（摘要） |

- **共同机制**：笼统分数把很多属性压成一个数，哪一项都能拿分；针对单一属性构造的测试（干预对、逐项问题、专门的同步评分）才分得开。和收敛 1 是同一件事的测量面。
- **边界**：SyncReward 自己的留出 bench 上 Spearman 79.7 / 70.5 / 68.1 / 82.1，说明「专门为一个属性收集的人评」训出的 RM 可以很好——问题在笼统和来源混杂，不在 learned RM 本身。没有一篇把 SyncReward 和 VA-Judger 放在同一人评集上比。
- **P9 检查**：本期没有论文给「按失败类别的平均 reward」，不能直接检验 P9；但 IsoVRBench（总分最高的 VideoReward 73.3、帧顺序只有 60.8）和 Self-Verifier 的人评失败标签（动作 / 姿态 41–44%、空间关系 33–36%）都是「总分盖住分层失败」的又一例，与 P9 前提一致，不计独立验证。
